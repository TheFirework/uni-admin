## Why

当前登录页面虽然功能完整，但用户体验存在明显不足：输入框缺少清空图标导致操作效率低、聚焦效果平淡缺乏视觉反馈、错误提示使用全局弹窗遮挡视线、移动端响应式细节不够友好。作为内部管理系统，登录是用户每天接触的第一个界面，其体验直接影响工作效率和系统专业度。本次优化旨在通过 5 项核心改进，将登录页面的交互体验提升至现代化水准。

## What Changes

### P0 - 核心优化（必须实现）

- **输入框清空图标**：为用户名、密码、验证码三个输入框添加 `clearable` 属性，支持一键清空内容，减少手动删除操作
- **聚焦效果增强**：为所有输入框添加聚焦时的边框颜色渐变、柔和阴影效果及微上浮动画，提供清晰的视觉反馈
- **响应式细节优化**：
  - 移动端输入框高度从 48px 调整至 52px（符合触摸友好的最小 44px 标准）
  - 卡片内边距在不同断点自适应（桌面端 48px→平板 32px→手机 24px）
  - 标题字号在移动端适当缩小（28px → 24px）

### P1 - 强烈推荐（显著提升体验）

- **键盘快捷键支持**：
  - Enter 键快速提交表单（当前已支持，需确保无冲突）
  - Tab 键切换顺序优化：用户名 → 密码 → [验证码] → 记住我 → 忘记密码链接 → 登录按钮 → 循环回用户名
  - Shift+Tab 支持反向切换
- **错误提示混合模式**：
  - 字段级验证错误改为内联提示（紧贴输入框下方显示），替代当前的 ElMessage 全局弹窗
  - API 级错误（如 401 未授权）继续使用 ElMessage 通知
  - 错误信息添加图标前缀，提升可读性

### 不包含在此 MVP 范围内

- 浮动标签（Floating Label）动画 - 需要新建组件，工作量较大，计划第二轮实现
- 加载状态骨架屏/进度条动画 - 属于锦上添花功能，优先级较低

## Capabilities

### New Capabilities

- `login-input-enhancements`: 登录页面输入框交互增强能力集，包括清空图标、聚焦效果、响应式优化
- `login-keyboard-accessibility`: 登录页面键盘无障碍访问能力，包括快捷键支持和焦点管理
- `login-error-display`: 登录页面错误展示策略优化，定义内联错误与全局通知的混合模式

### Modified Capabilities

（无现有 spec 需要修改，本次变更为全新能力）

## Impact

### 受影响的代码文件

| 文件路径 | 变更类型 | 说明 |
|---------|---------|------|
| `apps/web/src/views/login/components/LoginCard.vue` | **主要修改** | 输入框组件优化、样式重构、键盘事件监听 |
| `apps/web/src/views/login/index.vue` | 轻微修改 | 可能需要调整错误处理逻辑（如果改动错误提示方式） |
| `apps/web/src/assets/styles/_variables.scss` | 可选扩展 | 如需新增设计变量（如聚焦动画时长） |

### 受影响的依赖和技术栈

- **Element Plus**：使用原生 `clearable` 属性、`:deep()` 样式穿透、过渡动画
- **Vue 3 Composition API**：`onMounted`/`onUnmounted` 生命周期钩子（用于键盘事件监听）
- **VeeValidate**：保持现有表单验证逻辑不变，仅调整错误信息展示方式
- **SCSS 变量系统**：复用已有的 `$primary-color`、`$transition-base`、`$input-focus-shadow` 等变量

### API 和数据流影响

- **无 API 变更**：前端纯 UI 优化，不涉及后端接口调整
- **无数据库变更**：不影响数据模型
- **状态管理影响**：AuthStore 的 login 方法无需修改，但 index.vue 中的错误处理逻辑可能需要适配新的错误展示模式

### 受影响团队/角色

- **前端开发团队**：主要实施者，负责 LoginCard.vue 的代码修改
- **UI/UX 设计师**：（可选）审核视觉效果的最终呈现是否符合设计规范
- **QA 测试团队**：需要在桌面端、平板、手机三种设备上测试以下场景：
  - 清空图标功能（有值显示/点击清空/空值隐藏）
  - 聚焦效果（边框变色、阴影、上浮动画）
  - 响应式布局（不同屏幕尺寸下的表现）
  - 键盘导航（Tab 切换顺序、Enter 提交）
  - 错误提示（字段错误内联显示、API 错误全局通知）

### 回滚方案

如遇严重问题需要回滚：

1. **Git 回滚**：直接 `git revert` 本次提交即可恢复到优化前的状态
2. **配置开关（可选）**：可在后续版本中通过 feature flag 控制是否启用新特性，便于灰度发布
3. **渐进式发布建议**：先在测试环境验证，再在生产环境发布，观察用户反馈

### 风险评估

| 风险项 | 概率 | 影响 | 缓解措施 |
|-------|------|------|---------|
| Element Plus 样式穿透失效 | 低 | 中 | 使用官方推荐的 `:deep()` 选择器，并在 Chrome DevTools 验证 |
| 移动端兼容性问题 | 低 | 中 | 在 iOS Safari 和 Android Chrome 实机测试 |
| 键盘事件与其他组件冲突 | 低 | 低 | 使用命名空间的事件监听，在组件卸载时移除 |
| 用户习惯改变导致困惑 | 低 | 低 | 新特性均为渐进式增强，不破坏原有操作流程 |

5. ✅ Tab 键按预期顺序切换，Enter 键可提交表单
6. ✅ 字段验证错误以内联方式显示在对应输入框下方
7. ✅ API 错误仍以全局通知形式展示，不被遮挡
8. ✅ 无 TypeScript 类型错误，ESLint 检查通过
9. ✅ 无视觉回归（原有功能不受影响）
